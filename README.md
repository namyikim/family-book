# 가족의 시간
가족별 생애 기록을 정리하고 책으로 모으는 한국어 반응형 사이트. 여행노트처럼 상단 탐색과 왼쪽 메뉴, 오른쪽 기록 편집으로 구성합니다.

## 기능
- 상단 가족 이름 탭, 인물 추가·수정, 생일·소개·부모·배우자 관계
- 왼쪽 출생·유년기·학창 시절·청년기·결혼과 가족·직장과 활동·중년 이후
- 연도/연월/날짜 단위 사건, 제목·본문·장소·출처·사진, 검색, 수정·삭제
- 가족 관계 보기, 가족별 연대순 인쇄/PDF 저장
- PDF 책 만들기: "책으로 모아보기"의 **PDF 책 만들기** 버튼을 누르면 인쇄 창 없이 브라우저 안에서 자서전 형식의 PDF(신국판 152×225mm)를 만들어 내려받음. 표지 → 차례 → 사람마다 이야기 첫 장(이름·출생·소개), 생애 단계별 글과 사진, 연보 → 판권. 본문 나눔명조, 작은 글씨·한자 나눔고딕(`fonts/`, SIL OFL)이며 쓰인 글자만 PDF에 넣음. PDF 도구는 `lib/`의 pdf-lib·fontkit(MIT)을 그대로 둔 것으로, 버튼을 처음 누를 때만 불러옴. 기록과 사진은 복호화된 상태로 기기 안에서만 쓰임(`bookpdf.js`).
- 실제 개인정보 없는 가상 예시 모드
- 암호화 백업 다운로드와 서버 전송 실패 시 암호화된 기기 복구본
- 기록 가져오기: `{"version":1,"people":[…],"events":[…]}` 형식의 평문 JSON 파일로 사람과 기록을 한 번에 추가. 같은 id나 같은 이름(괄호·공백 무시)의 사람에게 붙이고, 같은 id 또는 같은 사람·시기·제목의 기록은 건너뜀. 기존 인물 정보와 기록은 바꾸지 않음. 단, 기록에 `"update": true`를 붙이면 같은 사람의 같은 id 기록에서 파일에 적힌 항목만 바꿈(사진은 `photos`가 있을 때만 교체). id를 모르면 `"match": {"stage": "출생"}`으로 그 사람의 해당 단계 기록(하나일 때만)을 찾고, `"fields": ["place"]`처럼 바꿀 항목을 좁힐 수 있음. 가져오기 파일은 평문이므로 사용 후 삭제 권장.
- 받은 기록함: 로그인하면 사이트가 열쇠 한 쌍을 만들어 개인 열쇠는 암호화된 기록 안에, 공개 열쇠는 비공개 저장소의 `inbox/public-key.json`에 둠. `node tools/inbox-seal.cjs inbox/public-key.json 가져오기.json 잠근파일.json`으로 잠근 파일을 `inbox/`에 올리면, 다음 로그인 때 기록 가져오기와 같은 규칙으로 합칠지 묻고 저장 후 그 파일을 지움. 기록 비밀번호를 다른 사람(또는 Claude)에게 주지 않고도 기록을 보낼 수 있음.

## GitHub 구성
1. `family-book`: 사이트 코드만 보관. 개인 기록 및 사진 원본 금지.
2. `family-data`: 반드시 **Private**. README로 초기화. `family.enc.json`에 기록이, `photos/`에 사진이 각각 암호화되어 저장됨. Pages를 켜지 마세요.
3. 코드 저장소 Settings → Pages → main / root 배포.
4. 사용자가 직접 GitHub fine-grained token을 발급: **family-data만 선택**, Contents Read and write. 사이트 코드 저장소 권한은 필요 없음.
5. 사이트에서 계정·family-data·토큰·9자 이상 비밀번호로 접속. 첫 저장 시 암호문 파일 생성. 다른 기기도 동일한 토큰/비밀번호로 연결. 로그인 유지 선택 시 연결 정보를 기기별 AES-GCM 키로 암호화해 이 브라우저의 IndexedDB에 보관합니다. 로그아웃하면 삭제됩니다. 토큰 만료·사이트 데이터 삭제·다른 브라우저에서는 다시 로그인해야 합니다. 같은 브라우저를 사용하는 사람이나 같은 출처의 스크립트는 자동 로그인으로 기록에 접근할 수 있으므로 공용 기기에서는 해제하세요.

## 보안과 한계
- PBKDF2-SHA256 600,000회 + AES-256-GCM. 매 저장마다 새 salt/IV. 키·비밀번호·토큰은 저장소에 업로드하지 않음.
- 매 읽기/쓰기 전 Private 여부 확인. 공개 저장소이면 저장 거부. 내용은 잠금 해제 전 렌더링하지 않음.
- 충돌은 GitHub SHA로 감지하며 자동 덮어쓰지 않음. 실패 시 백업 다운로드 후 다른 기기 변경과 비교 필요.
- 저장 전 암호문만 localStorage 복구본으로 보관. 정상 저장 후 삭제. 브라우저 복구본 저장 실패 시에도 서버 저장을 시도하고, 서버 실패 시 입력을 현재 화면에 보존.
- 사진은 브라우저 캔버스로 긴 변 1,400px JPEG 재인코딩 (일반 EXIF 위치정보 제거). 원본 보관용 아님.
- 사진은 기록 파일과 따로, 사진마다 새 열쇠(AES-256-GCM)로 암호화해 `photos/<번호>.enc.json`에 저장. 사진 열쇠는 암호화된 기록 안에만 있으므로 기록 비밀번호 없이는 열 수 없음. 8MB 한도는 사진을 뺀 글 기록에만 적용되어 사진 수에는 사실상 제한 없음. 예전처럼 기록 안에 들어 있던 사진(가져오기·받은 기록함 포함)은 그대로 보이며, 로그인하거나 저장할 때 자동으로 따로 옮겨짐. 700KB가 넘는 사진은 긴 변 1,400px로 줄여 저장.
- 암호화 백업은 따로 저장된 사진을 다시 기록 안에 넣어 한 파일로 내려받음(사진이 많으면 파일이 큼).
- 비밀번호 분실 시 복구 불가. 백업은 사용한 비밀번호와 함께 안전하게 별도 보관. 복원은 비공개 저장소 family.enc.json 교체로 가능 (현재 파일 먼저 백업).
- GitHub 과거 커밋에는 삭제 전 암호문도 남음. 삭제 버튼은 과거 버전까지 지우지 않음.
- 공개 사이트 코드가 변조되거나 기기/확장프로그램이 감염된 경우 잠금 해제된 정보 보호 불가. 사이트 코드 쓰기 권한 최소화와 GitHub 2FA 권장.
- PDF 인쇄는 평문을 사용자 기기에 저장하므로 파일 공유에 주의.

## 개발
Node.js 22 이상, 설치할 의존성 없음(`lib/`에 PDF 도구 포함). `npm test`, `npm run check`.
`python3 -m http.server 8000`으로 localhost 확인. 암호화는 HTTPS 또는 localhost 필요.

## 현재 배포 상태
코드 저장소: https://github.com/namyikim/family-book
GitHub Pages 설정: Settings → Pages → Deploy from a branch → main / (root).
데이터 저장을 시작하기 전에 family-data를 Private로 생성하고 기록 전용 토큰을 연결하세요.

## 비밀번호 로그인
최초 연결 후 토큰·저장소 정보를 기록 비밀번호로 암호화하여 이 브라우저에 보관합니다. 로그아웃하면 자동 로그인 키는 삭제되며, 암호화된 연결 정보는 남아 다음 접속에 비밀번호만 사용할 수 있습니다. 새 기기·사이트 데이터 삭제·토큰 만료 시에는 연결 설정이 필요합니다.
